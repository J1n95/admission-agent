# 2026-10-18：五分制成绩与证据编号修复

## 用户发现与产品判断

用户检查桌面报告时指出：输入西南交通大学 3.5/5 GPA 后，案例对照展示约 68.5 的“985 等效分”和偏低的成功案例名次；分析页还向用户暴露 `[e_...]` 形式的内部证据 ID。用户进一步明确，demo 的关键“出差错”指某些专业方向下项目筛选、机会参考值或分析内容极不合理，不能仅用程序能运行作为验收标准。

## 根因与取舍

- 旧 `case-analysis.mjs` 将 `3.5/5` 线性换为 `70/100`，再扣院校层次修正 1.5，得到 68.5；没有成绩单上的官方百分制换算依据。这种数值会污染成功案例位置比较和模型输入。
- 部分采集记录也把非百分制 GPA 除以满分写进 `gpa100`。即便只修表单换算，旧数据库值仍可能导致跨分制比较。
- 桌面运行时实际引用 `miniprogram/cloudfunctions/admissionApi/agent/` 内的旧 Agent 副本；只修改仓库根目录文件并不能覆盖完整流程。桌面测试首先暴露两份行为资产不一致，随后同步修正。
- 决策：保留申请人原始 GPA。4/4.3/5 分制只和已标明同分制的成功案例比较；没有同分制案例则不给 GPA 名次或虚构百分制等效分。若成绩单确有官方百分制加权均分，可改选百分制输入。模型机会参考值仍允许生成，但须解释样本与分制限制，不能称为真实录取率。
- 内部证据 ID 保留用于校验，报告和导出将 `[e_...]`、`[c_...]` 替换为可对照的“资料 1、资料 2”；不是删除证据。

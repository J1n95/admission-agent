# 申请分析 Agent｜岗位演示说明

## 一句话介绍

一个面向港新硕士申请规划的本地桌面 Agent：用少量表单背景筛选项目，再结合本地已审核的成功案例和项目资料，输出单项目分析与跨项目排序；结果会标注证据数量和不确定性。模型百分比是未经真实录取结果校准的参考值，不是真实录取率。

## 演示想展示的产品判断

公开成功案例很少时，直接给 GPA 名次容易把少量样本误说成硬门槛；表单留白也不能被当成申请人没有某项经历。本版本让 1–4 条可比较案例不输出成绩名次，并在横向排序时把低样本量和资料缺口反映为低置信度及更宽区间。未填写的实习/科研信息应作为待核实或文书材料建议，而不是自动降分的事实。为保持快速填写，不额外要求申请人把每段实习的任务与成果拆成必填字段。

## 三分钟演示路径

1. 输入一份简短申请人资料（建议用教育或心理合成样例，不用真实学生隐私数据）。
2. 展示“项目筛选”：Agent 根据用户指定地区、方向和专业背景，解释保留与排除项目的理由。
3. 打开一个只有 2–3 条公开成功案例的项目：查看案例数、GPA 可比性、官方资料缺口及宽区间；说明系统不会把两三条成功样本冒充录取门槛。
4. 展示跨项目排序：按模型参考值从高到低排列，并让面试官看到排序理由、低置信度和需要申请人自行核实的信息。
5. 如被问到模型：说明桌面端允许用户配置兼容的 Chat Completions API；API Key 在本机加密保存，但分析请求和输入资料会发送给用户指定的模型服务商。

## 实测片段

2026-10-18 使用六份合成背景完成 24 次 DeepSeek Flash 调用，覆盖金融、传媒、法律、公共卫生、教育、心理；每份资料各做一次筛选、两次单项目分析和一次跨项目排序。教育场景中，2 条案例项目展示 58%（36–76%），10 条案例项目展示 52%（33–70%），两者都标为低置信度；心理场景只有 2–3 条案例，结果也不展示 GPA 名次并保留宽区间。以上是固定场景下的模型输出，不足以证明数值准确。

复测还发现程序曾把一句明确的否定表述误判为“声称语言达标”，导致有效分析被隐藏。修正后用原始响应离线复核，没有额外调用模型；这是校验规则的改进，不是模型能力提升。完整测试方法、所有结果及限制见 [非工科申请分析 Agent 复测记录](cross-discipline-eval-2026-10-18.md)。

## 演示前检查

- 使用本机 API 设置，不要把 API Key 放进截图、简历、仓库或发给招聘人员的压缩包。
- 现场优先使用合成资料；如要输入真实申请人信息，先取得同意并评估数据传给 API 服务商的风险。
- [0.1.14 Windows ZIP](https://github.com/J1n95/admission-agent/releases/tag/v0.1.14) 已公开下载，但未签名，Windows 首次运行可能提示安全确认。收件人需要自行配置模型 API 才能完成实时分析。
- 项目与案例资料是随包快照，不代表实时联网核验；语言只比较已收录的考试总分，不校验单项要求。
- 演示时明确提示：百分比未用真实录取/拒录结果校准，不能当成录取保证。

## 本地数据包

本地演示包携带 3,435 条通过审核并满足年份筛选的案例、5,279 份官方资料，覆盖 834 个有官方资料的项目（项目目录快照 832 项）。这些是包内数据量，不代表各项目资料同等完整或全部仍为最新；演示时应展示来源与更新时间，而不是把总量包装成覆盖率或质量分数。

## 复测边界

这是产品功能与异常处理的演示，不是模型横向对比，也不是准确率实验。没有真实录取结局、真实申请者可用性测试或逐条官方事实/引用审查。费用按服务商 token 用量和本地价格估算约 ¥0.41，尚未与实际账单核对。不得把本轮描述成“概率准确率提高”“已找到最佳模型”或“所有专业都已验证”。
